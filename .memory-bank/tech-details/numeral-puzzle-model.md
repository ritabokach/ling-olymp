# Модель задачи «система счёта»

> Стартовая идея, её можно обсуждать. Финальные решения фиксировать в `.memory-bank/decisions.md`.

## Параметры придуманного языка

- **Основание:** 10, 20 или смешанное (например, 20 с подсистемой на 5, как во многих реальных двадцатеричных системах).
- **Словарь:** придуманные слова для базовых элементов. Генерируются по простым фонетическим правилам (например, слоги согласный + гласный), чтобы звучать как настоящий язык.
- **Схема сборки:** порядок множителя и основания («три-двадцать» или «двадцать-три» для 3×20); порядок слагаемых (крупное первым или последним).
- **Служебное слово:** есть ли соединитель («и») между частями.

## Упрощения MVP

- Числительное — отдельные слова через пробел. Слитного написания нет; сегментацию слов добавим позже.
- Диапазон чисел — например, до 399.

## Задача

- **Примеры:** N пар «запись на языке ↔ число».
- **Вопросы:** перевести несколько новых чисел в обе стороны.

## Проверка однозначности — сердце проекта

- Решатель перебирает **все гипотезы**: структурные параметры × сопоставление слов и значений, совместимые с примерами.
- Метод не выбран: перебор с возвратом (backtracking) или решатель ограничений.
- **Критерий:** все совместимые гипотезы дают **одинаковые ответы** на вопросы задачи. Это мягче, чем «правило ровно одно», и ближе к настоящим олимпиадным задачам.
- Ответы расходятся → генератор добавляет пример или пересобирает задачу.
- Дополнительно: оценка сложности — сколько гипотез отсекает каждый пример, сколько примеров нужно.
